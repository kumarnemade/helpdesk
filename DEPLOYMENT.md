# Deploying to Render (free)

The app runs as one free Docker web service on Render (the API serves the built
client), with a free Supabase Postgres database. Gmail is read over IMAP and
replies are sent through the Gmail API, because Render's free plan blocks SMTP
ports. Total cost: $0.

| Piece | Where | Config |
|---|---|---|
| App (API + client) | Render free web service | `Dockerfile`, `render.yaml` |
| Database | Supabase free project | `DATABASE_URL` |
| Inbound email | Gmail IMAP (App Password) | `GMAIL_USER`, `GMAIL_APP_PASSWORD` |
| Outbound email | Gmail API (OAuth) | `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN` |
| Keep-awake | cron-job.org or UptimeRobot | pings `/api/health` |

**Free-plan limits**

- Render puts a free service to sleep after 15 minutes with no incoming
  requests (waking takes about a minute). While asleep, no email is read and
  no AI jobs run. The pinger in step 6 keeps it awake.
- Render gives 750 free hours a month, enough for this one service always on
  (don't run other free services in the same workspace).
- Render may restart a free service at any time. Jobs are stored in the
  database, so nothing is lost.
- Supabase: 500 MB database. It pauses a project after 7 days without
  activity; the always-on app keeps it active.

## 1. Push the code to GitHub

Render deploys from a Git repository. Create a repository on GitHub (private
is fine) and push this project to it. `.env` files are git-ignored. Check
they're not included before pushing.

## 2. Create the Supabase database

1. Sign up at https://supabase.com and create a project. Pick the region
   **Southeast Asia (Singapore)** to match `region: singapore` in
   `render.yaml`, and save the database password.
2. Click **Connect** and copy the **Session pooler** connection string
   (host `aws-…pooler.supabase.com`, port **5432**). Don't use the "Direct
   connection": it's IPv6-only and Render can't reach it. Don't use the
   transaction pooler (port 6543) either: migrations need session mode.
3. Replace `[YOUR-PASSWORD]` with the database password. If the password has
   symbols like `@`, `#` or `/`, URL-encode them (e.g. `@` → `%40`).

## 3. Get the Gmail API keys (for sending replies)

Use the same Gmail account as `GMAIL_USER`.

1. Go to https://console.cloud.google.com and create a project (e.g.
   "Helpdesk").
2. **APIs & Services → Library**: search for **Gmail API** and click
   **Enable**.
3. **Google Auth Platform** (OAuth consent screen): click **Get started**.
   Enter an app name and your email, choose **External**, and finish.
4. **Data access → Add or remove scopes**: add
   `https://www.googleapis.com/auth/gmail.send` and save.
5. **Audience → Publish app**, so the status is **In production**. This step
   matters: in "Testing" status Google expires the refresh token after 7
   days and email sending stops. You don't need Google's verification for
   your own account.
6. **Clients → Create client**: type **Web application**. Under **Authorized
   redirect URIs** add `https://developers.google.com/oauthplayground`.
   Create it, then copy the **Client ID** and **Client secret**.
7. Open https://developers.google.com/oauthplayground:
   1. Click the gear icon (top right), tick **Use your own OAuth
      credentials**, and paste the Client ID and secret.
   2. In **Step 1**, type `https://www.googleapis.com/auth/gmail.send` in the
      box and click **Authorize APIs**.
   3. Sign in with the helpdesk Gmail account. Google warns that the app
      isn't verified: click **Advanced → Go to … (unsafe)**. It's your own
      app. Then click **Continue**.
   4. In **Step 2**, click **Exchange authorization code for tokens** and copy
      the **Refresh token**.

You now have `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET` and
`GMAIL_REFRESH_TOKEN`. Keep them secret. To test locally first, put them in
`server/.env`. The server logs `replies emailed to customers via Gmail API`
at startup when they're picked up.

You also need the Gmail **App Password** for reading the inbox, if you don't
have it already: turn on 2-Step Verification for the account, then create one
at https://myaccount.google.com/apppasswords.

## 4. Create the Render service

1. Sign up at https://render.com with GitHub.
2. **New → Blueprint**, choose your repository. Render reads `render.yaml`.
3. Fill in the values it asks for:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Supabase session pooler string from step 2 |
| `GMAIL_USER` | the helpdesk Gmail address |
| `GMAIL_APP_PASSWORD` | its App Password |
| `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN` | from step 3 |
| `GOOGLE_GENERATIVE_AI_API_KEY` | optional: Gemini key for AI features |
| `SENTRY_DSN`, `VITE_SENTRY_DSN` | optional: leave empty to turn Sentry off |

   `BETTER_AUTH_SECRET` and `INBOUND_EMAIL_SECRET` are generated by Render.
   `CLIENT_ORIGIN` and `BETTER_AUTH_URL` default to the service's
   `https://….onrender.com` address. Set both only if you add a custom domain.
4. Click **Apply**. The first build takes a few minutes. Each start applies
   any new database migrations before the server starts. After that, every
   push to the repository's default branch deploys automatically.
5. When it's live, open `https://<your-service>.onrender.com/api/health`. It
   should show `"database":"ok"`.

## 5. Create the admin and AI agent users

Render's free plan has no shell, so run the seed scripts from your computer
against the Supabase database. In PowerShell, from `server/`:

```powershell
$env:DATABASE_URL = "<Supabase session pooler string>"
$env:SEED_ADMIN_EMAIL = "you@example.com"
$env:SEED_ADMIN_PASSWORD = "<12+ character password>"
bun run db:seed
bun run db:seed:ai-agent
Remove-Item Env:DATABASE_URL, Env:SEED_ADMIN_EMAIL, Env:SEED_ADMIN_PASSWORD
```

Variables set this way take precedence over `server/.env`, so your local
database isn't touched. Close the terminal afterwards so you don't run local
commands against production by mistake. Don't run `db:seed:tickets` in
production: it adds 100 demo tickets.

## 6. Keep the app awake

Set up a free pinger to request the health URL at least every 10 minutes:

- **cron-job.org**: create a cron job for
  `https://<your-service>.onrender.com/api/health`, every 10 minutes.
- or **UptimeRobot**: add an HTTP(s) monitor for the same URL, every 5
  minutes. It also emails you if the app goes down.

Each ping also queries the database, which keeps Supabase active.

## 7. Check everything works

1. Sign in with the admin account from step 5.
2. Email the helpdesk Gmail address from another account. Within a minute or
   two it should appear on **Tickets** (and be classified/auto-resolved if
   the Gemini key is set).
3. Reply to the ticket. The reply should arrive in the other account, in the
   same email thread. Reply to it, and your answer should appear on the
   same ticket.

If something fails, check the service's **Logs** tab on Render. A
`Gmail OAuth token request failed (400): … invalid_grant` error means the
refresh token was revoked or expired (e.g. the app was still in "Testing"):
publish the app (step 3.5) and create a new refresh token (step 3.7).
